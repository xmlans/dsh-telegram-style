# D30. 配色

- **取代**：D50、D64

## 背景

皮肤画的是宿主自己的界面，同一套界面要有几种整体的颜色，每种又分亮暗，亮暗由宿主决定。配色只换画出来的样子，不改功能的行为；把它写成功能里的分支，每张样式表都要知道当前是哪套配色。

## 决定

- 配色是一项偏好，三套各分亮暗：经典、玻璃、粉色。亮暗跟随宿主自己的亮暗切换，不另设开关；也没有「跟随宿主」这一档，皮肤始终自己作画。
- 令牌分三组：palette（每套配色各自的取值，亮暗各一份）、shared（各套共用的取值）、alias（把宿主令牌别名到皮肤令牌）。配色切换只靠令牌：一档整套重写别名与私有令牌，功能样式表一律读令牌。
- 皮肤自己定义的颜色令牌，每一档的亮暗都要有对应的取值，漏掉即构建失败。
- 强调色、强调文字色、强调填充色分工：强调色只画图标、下划线和进度线，强调文字色画链接和标签，强调填充色承载白字；字色与底色的每一对组合由对比度测试核对。
- 字体固定为系统字体栈加随包分发的 JetBrains Mono，不是偏好。
- 配色加一档，功能样式表不动。

## 后果

- 私有令牌每加一条，都要补进三套配色的亮暗六份取值。
- 功能样式表里画面的颜色一律读令牌；写死颜色会在别的配色下露馅。
- 玻璃配色依赖背景模糊，长会话里滚动可能变慢；这一点只能靠配色本身的取舍化解。
- 放弃的做法：为每套配色写一套按配色分支的规则；让读者自定义强调色与标志；跟随宿主令牌的一档。

## 重审条件

- 宿主提供主题层级或令牌分层机制时，配色改用宿主的层级。
- 读者需要自定义配色，或要在亮暗之外另设一档时，重新讨论偏好的形状。
